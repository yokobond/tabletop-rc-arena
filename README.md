# Tabletop RC Sumo Arena

木製デスクの上で2台のRCカーを体当たりさせ、相手をテーブルの端から突き落とす A-Frame 製の3D対戦ゲームです。外部3Dモデル・音声ファイルは使わず、すべてプロシージャルに生成しています。物理演算は Rapier、オンライン対戦は Croquet で動きます。

```bash
npm install
npm run dev     # 開発サーバー
npm test        # 物理・CPUのテスト
npm run build   # 型チェックと本番ビルド
```

| 操作 | 1P | 2P |
| --- | --- | --- |
| 走行 | `W` `A` `S` `D` | `↑` `←` `↓` `→` |
| ブースト | `Space` | `Enter` / `Shift` |

`Esc` または `P` で一時停止。CPU戦では矢印キーでも1Pを操作できます。タッチ操作は下部の「設定」から切り替えられます（タッチ端末では初期表示）。タッチ操作は「操作方式」で2種類から選べます。2人対戦では「1Pの操作方式」「2Pの操作方式」としてプレイヤーごとに選べるので、1Pはプロポ・2Pはスティックのように別々のコントローラーで対戦できます。

- プロポ（初期設定）：左手の指でハンドル、右手の指でアクセル・バック。アクセルを上に大きく押し上げるとブースト
- スティック：1本のスティックで操作。前方（外周のオレンジの弧）まで大きく倒すとブースト。パッドは札をドラッグして動かせ、ダブルタップで元の位置に戻る。対面配置では左右の端に向かい合わせで並ぶ

どの操作がどの車かは、車の頭上の札（1P / 2P / CPU、オンラインでは自分の車が YOU）と、タッチパッドの色・札で見分けられます。試合開始のカウントダウン中は、各車の操作方法も表示されます。

## オンライン対戦

タイトルの「オンライン対戦」を押すと、URL が `?q=…#pw=…` 付きになり、招待リンクが表示されます。同じリンクを開いた人が同じ机に入ります。

- 最初の2人がそれぞれ1台ずつ運転し、3人目からは観戦になります。空いている席の車はCPUが運転します
- 開始・一時停止・ルール変更は参加者全員に反映されます
- 各自の操作は `W` `A` `S` `D`（矢印キーも可）、タッチ、VRコントローラーです。表示は端末ごとに AR にできます（下の「AR」）
- タブを裏に回してしばらく経つと、Croquet の autoSleep によって席が空きます

仕組みは Croquet の複製計算（Ohshima et al., "Croquetify", Onward! '26）と、Microverse の物理構成にならっています。

- リフレクタは Croquet-in-a-Box です。URL を `.env.local` の `VITE_CROQUET_BOX` に書きます（例は `.env.example`）。`box` で指定するので、APIキーは要りません。リフレクタはイベントにタイムスタンプを付けて全員に配るだけで、ゲームの計算はしません
- `src/net/model.ts` の `SumoModel` は全員のブラウザで同じように実行されます。`future()` のループで Rapier ワールドを進め、届いた入力イベントを順番どおりに適用します
- 途中参加者には Croquet のスナップショットが渡されます。物理状態は Rapier の `world.takeSnapshot()` のバイト列だけに入っています。それ以外はルール値と剛体・コライダーの handle を JSON で持つだけです
- 操作の遅延は、リフレクタまでの往復時間で決まります

### 設定とデプロイ

サーバーの情報はリポジトリに入れず、Git の管理外にある `*.local` ファイルに書きます。

```bash
cp .env.example .env.local                # VITE_CROQUET_BOX を設定
cp .env.deploy.example .env.deploy.local  # DEPLOY_BASE と DEPLOY_TARGET を設定
npm run deploy                            # 型チェック、ビルド、rsync
```

## VR

WebXR 対応のブラウザとヘッドセットでは、タイトルに「VRで開始」が表示されます。

| 操作 | コントローラー |
| --- | --- |
| 走行 | スティック（左右どちらでも） |
| ブースト | トリガーまたはグリップ |
| 視点リセット | スティック押し込み |
| 一時停止 | B / Y |
| 決定（再開・リマッチ） | A / X |

ヘッドセットをかけた人が1Pです。2Pはキーボードで操作します。

WebXR は HTTPS か localhost でしか動きません。Quest で開発サーバーを開くときは、USB接続して次を実行し、ヘッドセットのブラウザで `http://localhost:5173` を開きます。

```bash
adb reverse tcp:5173 tcp:5173
```

実機がなくても、devDependency の `iwer`（WebXR エミュレータ）を読み込めばブラウザ上で動作を確認できます。

## AR

スマートフォンやタブレット（iPhone / iPad の Safari、Android の Chrome）では、カメラの映像に重ねて、現実のテーブルの上にアリーナを表示できます。WebXR を使わないマーカー方式なので、iOS でも動きます。

1. タイトルか試合中の「設定」にある「マーカーを表示・印刷」でマーカーを印刷します（黒い四角が 10cm になります）。別の端末の画面に表示して、テーブルに寝かせて置いてもかまいません
2. マーカーをテーブルの中央に平らに置きます。マーカーの上側がアリーナの奥、下側が手前（1P 側）です
3. 「AR表示（カメラ）」を押してカメラを許可し、マーカーを映します。マーカーの中心がアリーナの中心になります

- アリーナの大きさは「ARの大きさ」で選びます。テーブルの幅がマーカーの黒い四角の 4 / 6 / 9 倍になります（10cm のマーカーなら幅 40 / 60 / 90cm）
- 車が落ちるのはゲーム内のテーブルの端です。現実のテーブルがそれより広くても狭くても変わりません。端から出た車はテーブルの面より下で見えなくなります
- 同じマーカーを映した端末には、同じ位置にアリーナが表示されます。オンライン対戦で2台が1つのテーブルを囲むときは、「ARの大きさ」を同じ倍率にそろえてください
- AR はその端末の表示方法です。運転する人も観戦する人も使えます。離れた場所から参加する人は、それぞれの場所にマーカーを置けば、そこに同じ試合が表示されます
- 操作はタッチパッド（キーボードも可）のままです

制限があります。

- マーカーがカメラに映っている間だけ位置を合わせられます。見失うと最後の視点のまま表示が続き、「マーカーをカメラに映してください」と表示されます。低い角度や遠くからだと表示が揺れやすくなります
- 手やテーブルの上の物がアリーナの手前にあっても、アリーナは常にその上に描かれます
- カメラのレンズの画角は取得できないので、一般的なスマートフォンの背面カメラの値で計算しています。画面の端ではずれることがあります

カメラは HTTPS か localhost でしか使えません。開発中に LAN 内の端末から開くときは、自己署名証明書の HTTPS で開発サーバーを起動します（端末側で証明書の警告を承認します）。

```bash
npm run dev -- --mode https --host
```

マーカーの検出と姿勢の推定には [js-aruco2](https://github.com/damianofalcioni/js-aruco2) を使っています。

## 構成

- `src/game/` — DOMに依存しないシミュレーション
  - `physics.ts`：Rapier ワールドのラッパー
  - `carParts.ts`：車体パーツの定義
  - `engine.ts`：走行・得点・復帰などのルール
  - `ai.ts`：CPU
  - `stages.ts`：ステージ定義
- `src/ar/` — AR のマーカー（`marker.ts`）、マーカーからカメラの位置を求める計算（`markerPose.ts`）
- `src/net/` — Croquet のモデル（`model.ts`）、ビューとセッション（`session.ts`）
- `src/runtime/` — 入力、Web Audio 効果音、React との共有ストア
- `src/aframe/` — A-Frame コンポーネント、複合モデル、Canvas テクスチャ、VR（`vr.ts`）、AR（`ar.ts`）
- `src/ui/` — React の HUD・操作ドック・タッチパッド
