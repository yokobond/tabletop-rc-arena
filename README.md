# Tabletop RC Sumo Arena

木製デスクの上で2台のRCカーを体当たりさせ、相手をテーブルの端から突き落とす A-Frame 製の3D対戦ゲームです。外部3Dモデル・音声ファイルは使わず、すべてプロシージャルに生成しています。物理演算は Rapier、オンライン対戦は Croquet で動きます。

```bash
npm install
npm run dev     # 開発サーバー
npm test        # 物理・CPUのテスト
npm run build   # 型チェックと本番ビルド
```

| 操作 | 1P | 2P |
| --- | --- | --- |
| 走行 | `W` `A` `S` `D` | `↑` `←` `↓` `→` |
| ブースト | `Space` | `Enter` / `Shift` |

`Esc` または `P` で一時停止。CPU戦では矢印キーでも1Pを操作できます。タッチ操作は下部の「設定」から切り替えられます（タッチ端末では初期表示）。タッチ操作は「操作方式」で2種類から選べます。2人対戦では「1Pの操作方式」「2Pの操作方式」としてプレイヤーごとに選べるので、1Pはプロポ・2Pはスティックのように別々のコントローラーで対戦できます。

- プロポ（初期設定）：左手の指でハンドル、右手の指でアクセル・バック。アクセルを上に大きく押し上げるとブースト
- スティック：1本のスティックで操作。円の外にある前方の BOOST エリアまで大きく押し込むとブースト。パッドは札をドラッグして動かせ、ダブルタップで元の位置に戻る。対面配置では左右の端に向かい合わせで並ぶ

どの操作がどの車かは、車の頭上の札（1P / 2P / CPU、オンラインでは自分の車が YOU）と、タッチパッドの色・札で見分けられます。試合開始のカウントダウン中は、各車の操作方法も表示されます。

## テーブルの大きさ

タイトルか試合中の「設定」にある「テーブル」で、テーブルの大きさを 標準 / 1.25倍 / 1.5倍 / 2倍 から選べます。テーブルが大きいほど端までの余裕が増え、車を落とさずに走らせやすくなります。

- 車や机の上の物の大きさは変わりません。物とスタート位置は、テーブルの絵と一緒に同じ割合で外へ広がります
- ステージを切り替えても、選んだ大きさのままです。大きさは端末が覚えていて、次に開いたときも同じ大きさで始まります
- 試合中に変えると、ステージを変えたときと同じように試合が最初からになります
- 「カスタム」のアリーナは、作ったときのテーブルの大きさを持っています。大きいテーブルで詰めて並べたアリーナは、小さくするとスタート位置や小物が重なって置けなくなることがあり、その大きさは選べません
- オンラインでは、ステージと同じく、アリーナを編集できる人だけが変えられます

## アリーナ編集

タイトルの「アリーナを編集」を押すと、机を上から見た画面になり、机の上の物を並べ替えられます。

- 物をドラッグして動かします（マウスでもタッチでも）。車の下の輪はスタート位置で、同じように動かせます
- 「置く」でマグ・本・高台・スロープ・鉛筆・消しゴムを追加します。障害物は 16 個、小物（鉛筆・消しゴム）は 8 個までです
- 選んだ物は「左に回す」「右に回す」で 15° ずつ回し、「削除」で取り除きます。キーボードなら `R`（`Shift` + `R` で逆回り）と `Delete` です
- 選んだ物は「大きく」「小さく」で、形の比率を保ったまま 1.2 倍ずつ大きさを変えられます（キーボードなら `+` と `-`）。大きさには上限と下限があります。大きくすると置けなくなる場合（スタート位置にかかる、鉛筆や消しゴムが障害物に重なる）は、ボタンが押せません。鉛筆と消しゴムは、大きいほど重くなります
- 「テーブルの絵」で天板の絵柄を土俵・木目・サーキット・方眼から選べます。「画像」を押すと、端末の画像を天板に貼れます。画像はテーブルの形（3:2）に切り抜かれます
- 「テーブル」でテーブルの大きさを変えられます（上の「テーブルの大きさ」と同じものです）。大きさだけを変えた場合、ステージは「カスタム」にならず、ひな形のままです
- 「ひな形」で3つのステージのどれかから並べ直せます。「元に戻す」で直前の状態に戻ります

置けない場所があります。ドラッグ中に輪が赤くなったら、そこには置けません（離すと元の位置に戻ります）。

- スタート位置のすぐそばには、障害物も小物も置けません
- 鉛筆と消しゴムは、障害物やほかの小物と重ねられません。障害物どうしは重ねられます
- 車が落ちたあとに戻ってくる場所は、障害物と小物を避けて自動で決まります

編集中のアリーナは、ステージの「カスタム」としてその端末に自動で保存されます（画像も一緒に）。次に開いたときも「カスタム」を選べば同じアリーナで遊べます。

### 保存と読み込み

編集画面の「保存・読み込み」を押すと、アリーナを名前を付けて残したり、呼び出したりできます。

- 「端末に保存」で、机の上のアリーナをその名前で端末に保存します。同じ名前があれば上書きします（確認が出ます）。30 件まで保存できます
- 「保存済み」の「読み込む」で、そのアリーナを机の上に出します。それまでのアリーナは置き換わりますが、「元に戻す」で戻せます。「削除」は元に戻せません
- 「ファイルに書き出す」で、アリーナを 1 つのファイル（`名前.arena.json`、テーブルの画像も入ります）としてダウンロードします。「ファイルから読み込む」で、ほかの端末で書き出したファイルを読み込めます
- オンラインでは、読み込みはアリーナの編集と同じ扱いです。編集できる人が読み込むと全員のアリーナが変わります。保存と書き出しは自分の端末だけのことなので、見えているアリーナを誰でも残せます

保存先はブラウザの中（レイアウトは localStorage、画像は IndexedDB）です。ブラウザのサイトデータを消すと、保存したアリーナも消えます。残しておきたいアリーナはファイルに書き出してください。

## 車をつくる（ガレージ）

タイトルの「車をつくる」を押すと、ガレージで車のボディを組み立てられます。シャシー（車台・バンパー・タイヤ）はそのままで、その上に身の回りの物をくっつけます。

- 下のトレイから物（消しゴム・ブロック・積み木・マッチ箱・定規・鉛筆・キャップ・乾電池・紙コップ・ピンポン玉）を車の上へドラッグして離すと、そこにくっつきます。置ける場所は緑、置けない場所は赤の影で表示され、トレイの上や車の外で離すと戻ります（キーボードでは `Enter` キーでも置けます）
- トレイの最後の「部品をつくる」で、自分の部品を作れます。形（箱・筒・玉）、大きさ（1〜30cm）、重さ（5〜200g）、色、名前を決めると、トレイに並んでほかの物と同じようにくっつけられます。作った部品は端末に保存され、トレイの鉛筆マークで直したり捨てたりできます。直したり捨てたりしても、もう車についている物はそのままです。車についた物は自分の形を持っているので、オンライン対戦の相手にも同じ形で見えます
- 作った部品はファイルに書き出して、ほかの端末や友だちに渡せます。部品づくりの画面の「ファイルに書き出す」でその部品を1つ、トレイの「書き出す」で作った部品をぜんぶ、1つのファイル（`○○.parts.json`）にします。トレイの「読み込む」でファイルを選ぶと（いくつでも）、トレイに並びます。STL から作った部品は形のデータもファイルに入るので、ファイルだけで持ち運べます。もうトレイにある部品は、二重には入りません
- 部品づくりの「STLファイルからつくる」で、3D プリンタ用の STL ファイル（バイナリでもテキストでも）を部品にできます。見た目は STL の形のまま（三角形 1500 こまでに間引きます）で、ぶつかったりくっついたりする形は、STL の内側に収まるいちばん大きな箱・筒・玉が自動で選ばれます（ほかの形にも変えられます）。ヒレや先のとがったところのような細い出っぱりは、ぶつかる形に入りません。筒や玉が部品の決まり（ふとさ 16cm まで）より太くなるときは、そのぶん細くして内側に収めます。1cm より薄い物だけは、部品の決まりで少しはみ出します。薄くて曲がった物（フォークなど）のように自動ではうまく合わないときは、「ぶつかる形をなおす」で大きさ・位置（左右・上下・前後）・筒の向き・箱のかたむき（3つの向きに −90〜90°）を自分で決められます。箱をかたむけると、車の上では箱がまっすぐのまま、見た目のほうがそのぶん逆にかたむいて付きます。決めた形は部品を直すときもそのまま残り、「じどうに もどす」で自動の形に戻せます。部品づくりの画面の左の絵は 3D で、ぶつかる形（赤い線）を好きな向きから近くで確かめられます。ドラッグ（矢印キー）で回し、右ドラッグ・Shift＋ドラッグ・2本指（Shift＋矢印キー）で動かし、ホイール・ピンチ・＋／−ボタンでカーソルや指の位置に向かってズームします。部品をダブルクリック（ダブルタップ）すると、そこが回転とズームの中心になります。↺ で向きと中心が元に戻ります。STL は mm 単位として読み、「おおきさ」でいちばん長いところを 1〜30cm にそろえます。重さのはじめの値は、PLA で中身 25% に 3D プリントしたときのめやすです。オンラインでは、STL の形はセッションのファイルサーバーに置いて相手に渡します（届くまでは、ぶつかる形がかわりに見えます）
- 試せる STL のサンプル（ロケット・ケーキフォーク・ボール・あきかん・チェスのポーン・L字アングル）を `/samples/` に置いています。タブレットではこのページからダウンロードして、「ファイル」アプリから選べます。サンプルは `node scripts/make-sample-stls.mjs` で作り直せます
- 置いた物はタップで選び、ドラッグで動かせます（0.5cmずつ・Shiftで0.1cmずつ）。物の真ん中だけでなく端や一部が触れていれば（ホットグルーは 3cm までのすき間があれば）そのまま自動ではみ出してくっつくので、ドラッグやタップだけで接着可能な範囲のどこにでも付けられます。その物を通してしか車につながっていない物（上に積んだ物など）は、一緒に動いたり回ったりします。選んだ物のまわりに3色の回転矢印（X・Y・Z）と上下移動の矢印が出るので、回転矢印をドラッグすると分度器の輪に沿って向きを変えられ（輪の中では15°ずつ・Shiftで5°ずつ、輪の外側へ引くと1°ずつ・Shiftで45°ずつ、クリック／タップで角度入力）、上下の矢印をドラッグすると高さを変えられます（0.5cmずつ・Shiftで0.1cmずつ、クリック／タップでcm入力）。斜めにしたり浮かせてすき間ができたりすると平らな面が合わなくなるので、瞬間接着剤でくっつけた物はホットグルーにくっつけ直されます（斜めの面どうしをぴったり合わせれば瞬間接着剤でもくっつけられます）。斜めの面に置いた物は、その面に沿って傾きます
- 何もない所をドラッグすると車を回して見られます（ホイール・ピンチで拡大縮小）
- 物は 14 個まで、重さにも上限があります。重い車ほど押されにくくなりますが、加速がにぶくなります
- 「決定！」でその車を使います。「いつもの車に戻す」で元のバギーに戻ります。作った車は端末に保存されます

くっつけ方は 2 種類です。左のパネルで、次に置く物のくっつけ方を選びます（初期設定はホットグルーです）。置いた物は「〜で付け直す」ボタンで、もう一方に変えられます。

| | ホットグルー | 瞬間接着剤 |
| --- | --- | --- |
| くっつく所 | すき間 3cm までなら何でも。すき間を埋めて固まります | 平らな面どうしがぴったり重なる所だけ（ピンポン玉や、鉛筆・乾電池の丸い側面には付けられません） |
| 強さ | 弱い | 強い（ホットグルーより強力で、くっつく面が広いほどさらに強い） |

以前の版で作った車の両面テープやセメダインは、ホットグルーになります。

対戦中、くっつけた物が相手の車や障害物にぶつかると、その物から車台までの間にある接着部が傷みます。傷みが強さを超えると、ホットグルーや瞬間接着剤がはがれて、そこから先の物がひとかたまりで外れて転がります。ブーストした相手からの体当たりは、特に効きます。外れた物は、車がテーブルから落ちて戻ってくると元どおりになります。

- 2人対戦では 1P と 2P、CPU 戦では 1P と CPU の車を、上のタブで切り替えて作れます
- オンラインでは「あなたの車」を 1 台作れます。運転している車がその形になり、全員の画面で同じように壊れます。CPU が運転する車はいつもの車です

### 車体を選ぶ（保存と読み込み・相手の車体）

ガレージ上部のネームプレートに、いま編集中の車の名前（まだ保存していない車は「名前なし」）と、保存していない変更があるかどうかが出ます。ネームプレートを押すと「車体を選ぶ・保存する」画面が開きます。タブレットの指操作で使いやすいよう、ボタンとカードは大きめです。

- 画面の上には「いま編集中の車」が出ます。名前のついた車なら「上書き保存」（変更がないときは「保存済み ✓」）、「名前を変える」、「別の車として保存」を、名前なしの車なら「名前をつけて保存」を押します。名前は専用の入力画面で入れるので、名前のついた車の名前をうっかり書き換えることはありません。ほかの車と同じ名前で保存しようとすると、上書きしてよいか確認が出ます（名前を変えるときは、ほかの車と同じ名前にはできません）。30 台まで保存できます
- 下には保存した車が 3D のサムネイル・パーツ数・重さ付きのカードで並び、編集中の車には「編集中」の印が付きます。カードを押すと、その車の大きなカードが開き、「この車にする」「名前を変える」「ファイルに書き出す」「消す」を選べます（カードを押しただけでは切り替わりません）。「消す」は確認が出て、消した車は元に戻せません
- 「＋ 新しくつくる」で、からっぽの車から作り始めます。ほかの車に切り替える前にいまの車が変更されていた場合は、その車に自動で上書き保存されます（名前なしの車は「マイカー」などの名前で保存されます）。ガレージの「元に戻す」でも前の車に戻せます
- どの保存した車を編集しているかは端末に覚えておくので、「決定！」のあとやページを開き直したあとも名前が出ます
- 「ファイルに書き出す」で、車体を 1 つのファイル（`名前.car.json`）としてダウンロードします。STL から作った部品の見た目データもファイルに入るので、ファイルだけでほかの端末や友だちに渡せます。「ファイルから読み込む」で書き出したファイルを読み込めます
- オンライン対戦で相手が「自分の車体を相手に提供」（初期設定は「提供しない」）を「相手に提供」にしているときは、一覧に「相手の車」のサムネイルが追加されます。相手の車を選んで切り替えると、相手の車についている自作部品や組み部品も、自分の車と同じようにタップして選んで右パネルの「トレイに入れる」で自分のトレイに入れられます（トレイに入った部品は独立したコピーになり、編集・削除しても元の車体には影響しません）

保存先はブラウザの中（localStorage）です。ブラウザのサイトデータを消すと、保存した車体も消えます。残しておきたい車体はファイルに書き出してください。

## オンライン対戦

タイトルの「オンライン対戦」を押すと、URL が `?q=…#pw=…` 付きになり、招待リンクが表示されます。同じリンクを開いた人が同じ机に入ります。

- 最初の2人がそれぞれ1台ずつ運転し、3人目からは観戦になります。空いている席の車はCPUが運転します
- 開始・一時停止・ルール変更は参加者全員に反映されます。得点と CPU の強さは誰でも変えられます
- ステージの選択とアリーナの編集は、アリーナマスターだけができます。セッションを最初に開いた人がアリーナマスターです
  - アリーナマスターは、タイトルのオンライン欄で「アリーナ編集」を「全員」にして誰でも編集できるようにしたり、「マスターを渡す」でほかの参加者に役割を渡したりできます
  - アリーナマスターは端末で覚えています。リロードしたり、タブが休止してから戻ったりしても、同じ端末ならアリーナマスターのままです
  - アリーナマスターがいない間は、いちばん長くいる参加者が代わりを務めます
  - 「カスタム」を選ぶか、編集画面の「保存・読み込み」から読み込むと、自分の端末に保存したアリーナ（画像つき）をそのセッションに持ち込めます
- 各自の操作は `W` `A` `S` `D`（矢印キーも可）、タッチ、VRコントローラーです。表示は端末ごとに AR にできます（下の「AR」）
- タブを裏に回してしばらく経つと、Croquet の autoSleep によって席が空きます

仕組みは Croquet の複製計算（Ohshima et al., "Croquetify", Onward! '26）と、Microverse の物理構成にならっています。

- リフレクタは Croquet-in-a-Box です。URL を `.env.local` の `VITE_CROQUET_BOX` に書きます（例は `.env.example`）。`box` で指定するので、APIキーは要りません。リフレクタはイベントにタイムスタンプを付けて全員に配るだけで、ゲームの計算はしません
- `src/net/model.ts` の `SumoModel` は全員のブラウザで同じように実行されます。`future()` のループで Rapier ワールドを進め、届いた入力イベントを順番どおりに適用します
- 途中参加者には Croquet のスナップショットが渡されます。物理状態は Rapier の `world.takeSnapshot()` のバイト列だけに入っています。それ以外はルール値と剛体・コライダーの handle を JSON で持つだけです
- 操作の遅延は、リフレクタまでの往復時間で決まります
- アリーナ（物の配置、スタート位置、テーブルの絵）もモデルの状態です。編集は「何をどこへ動かしたか」という操作として送られ、全員のモデルが `src/game/arena.ts` の同じ関数で適用します。2人が同時に別の物を動かしても、両方の変更が残ります
- テーブルに貼った画像は、Croquet の Data API でファイルサーバー（`<box>files`）に置きます。モデルが持つのはその名前だけで、各ブラウザが必要になったときに取りに行きます

### 設定とデプロイ

サーバーの情報はリポジトリに入れず、Git の管理外にある `*.local` ファイルに書きます。

```bash
cp .env.example .env.local                # VITE_CROQUET_BOX を設定
cp .env.deploy.example .env.deploy.local  # DEPLOY_BASE と DEPLOY_TARGET を設定
npm run deploy                            # 型チェック、ビルド、rsync
```

### 複数端末での確認と開発サーバーの更新

Croquet のセッションは、動いているモデルやビューのモジュールを差し替えることができません。そのため開発サーバー（`npm run dev`）では、Vite のホットリロードの代わりにページを読み込み直します。

- モデルに関わるコード（`src/net/` と、そこから読み込まれる `src/game/` など）を変えると、オンラインかどうかに関係なくページ全体を読み込み直します
- オンライン中は、どのファイルを変えても読み込み直します。URL に招待リンク（`?q=…#pw=…`）が残っているので、同じ開発サーバーにつないでいる端末はそろって読み込み直し、同じセッションに入り直します
- モデルのコードを変えると Croquet は別のセッションとして扱うので、それまでの招待リンクでは新しいセッションが始まります（全員がそろって入り直すので、開発中は問題になりません）
- オフラインで画面（React のコンポーネント）だけを変えたときは、これまでどおりホットリロードで差し替わります

LAN 内のタブレットやスマートフォンから開くときは `npm run dev -- --host`（カメラを使うときは `--mode https` も）で起動します。

## VR

WebXR 対応のブラウザとヘッドセットでは、タイトルに「VRで開始」が表示されます。

| 操作 | コントローラー |
| --- | --- |
| 走行 | スティック（左右どちらでも） |
| ブースト | トリガーまたはグリップ |
| 視点リセット | スティック押し込み |
| 一時停止 | B / Y |
| 決定（再開・リマッチ） | A / X |

ヘッドセットをかけた人が1Pです。2Pはキーボードで操作します。

WebXR は HTTPS か localhost でしか動きません。Quest で開発サーバーを開くときは、USB接続して次を実行し、ヘッドセットのブラウザで `http://localhost:5173` を開きます。

```bash
adb reverse tcp:5173 tcp:5173
```

実機がなくても、devDependency の `iwer`（WebXR エミュレータ）を読み込めばブラウザ上で動作を確認できます。

## AR

スマートフォンやタブレット（iPhone / iPad の Safari、Android の Chrome）では、カメラの映像に重ねて、現実のテーブルの上にアリーナを表示できます。WebXR を使わないマーカー方式なので、iOS でも動きます。

1. タイトルか試合中の「設定」にある「マーカーを表示・印刷」でマーカーを印刷します（黒い四角が 10cm になります）。別の端末の画面に表示して、テーブルに寝かせて置いてもかまいません
2. マーカーをテーブルの中央に平らに置きます。マーカーの上側がアリーナの奥、下側が手前（1P 側）です
3. 「AR表示（カメラ）」を押してカメラを許可し、マーカーを映します。マーカーの中心がアリーナの中心になります

- アリーナの大きさは「ARの大きさ」で選びます。テーブルの幅がマーカーの黒い四角の 4 / 6 / 9 倍になります（10cm のマーカーなら幅 40 / 60 / 90cm）。ゲームのテーブルを大きくしても現実での幅は同じで、そのぶん車が小さく表示されます
- 車が落ちるのはゲーム内のテーブルの端です。現実のテーブルがそれより広くても狭くても変わりません。端から出た車はテーブルの面より下で見えなくなります
- 同じマーカーを映した端末には、同じ位置にアリーナが表示されます。オンライン対戦で2台が1つのテーブルを囲むときは、「ARの大きさ」を同じ倍率にそろえてください
- AR はその端末の表示方法です。運転する人も観戦する人も使えます。離れた場所から参加する人は、それぞれの場所にマーカーを置けば、そこに同じ試合が表示されます
- 操作はタッチパッド（キーボードも可）のままです

制限があります。

- マーカーがカメラに映っている間だけ位置を合わせられます。見失うと最後の視点のまま表示が続き、「マーカーをカメラに映してください」と表示されます。低い角度や遠くからだと表示が揺れやすくなります
- 手やテーブルの上の物がアリーナの手前にあっても、アリーナは常にその上に描かれます
- カメラのレンズの画角は取得できないので、一般的なスマートフォンの背面カメラの値で計算しています。画面の端ではずれることがあります

カメラは HTTPS か localhost でしか使えません。開発中に LAN 内の端末から開くときは、自己署名証明書の HTTPS で開発サーバーを起動します（端末側で証明書の警告を承認します）。

```bash
npm run dev -- --mode https --host
```

マーカーの検出と姿勢の推定には [js-aruco2](https://github.com/damianofalcioni/js-aruco2) を使っています。

## 構成

- `src/game/` — DOMに依存しないシミュレーション
  - `physics.ts`：Rapier ワールドのラッパー
  - `carParts.ts`：車体パーツの定義
  - `bodyParts.ts`：ガレージで作るボディ（くっつける物と自分で作った部品、ホットグルーと瞬間接着剤の判定、設計の検証）
  - `carFile.ts`：車体のファイルの書き出しと読み込み（中身の確認・STL 見た目の同梱）
  - `partFile.ts`：作った部品のファイルの書き出しと読み込み（中身の確認）
  - `stlMesh.ts`：STL ファイルの読み込み、間引き、内側に収まる形（箱・筒・玉）の当てはめ、部品の見た目のバイト列
  - `engine.ts`：走行・得点・復帰などのルール
  - `ai.ts`：CPU
  - `stages.ts`：ステージ定義（ひな形）
  - `arena.ts`：アリーナの編集（操作の検証と適用）
  - `arenaFile.ts`：アリーナのファイル形式（書き出しと、読み込み時の検証）
- `src/ar/` — AR のマーカー（`marker.ts`）、マーカーからカメラの位置を求める計算（`markerPose.ts`）
- `src/net/` — Croquet のモデル（`model.ts`）、ビューとセッション（`session.ts`）
- `src/runtime/` — 入力、Web Audio 効果音、React との共有ストア、作った車と部品の保存（`designStorage.ts`）、車体のファイル（`carFiles.ts`）、アリーナの保存（`arenaStorage.ts`）とファイルの受け渡し（`arenaFiles.ts`）、テーブルの画像（`tableArt.ts`）、STL から作った部品の見た目（`meshStore.ts`）と部品のファイル（`partFiles.ts`）
- `src/aframe/` — A-Frame コンポーネント、複合モデル、Canvas テクスチャ、VR（`vr.ts`）、AR（`ar.ts`）、アリーナ編集のドラッグ操作（`editor.ts`）、ガレージの 3D 表示（`garageView.ts`）とくっつける物のモデル（`pieceMeshes.ts`）
- `src/ui/` — React の HUD・操作ドック・タッチパッド
